# 产品形态（已冻结）

**本仓做的是：以 Logseq OG 为笔记底座的新程序（数据层 = OG 的 Markdown 图）。**

不是下面任何一种「单独成品」：

| 不是 | 原因 |
|------|------|
| 只做 Cursor / ChatGPT skill | skill 只能在对话里写笔记；读书、视频、翻计划不在 IDE 里完成 |
| 只做 Logseq 插件 | 插件碰不到 Cursor 的 jsonl、也管不了 ChatGPT 导出；工程仓隔离要在仓外做 |
| 优化/魔改 Logseq 本体 | OG 是维护分支；fork Clojure/Electron 学不会、也难更新 |

对人：用 **Logseq 插件（RL）** 做设置和按钮；用 **Logseq OG** 打开图、翻双链。  
对程序：本仓 `repo_log` 是唯一引擎（`python -m repo_log serve`）。  
对入口（都调用同一引擎）：

1. **Logseq 插件** — `plugin/`：设置、工程、镜像、入库、斜杠命令
2. **本仓控制台** — `python -m repo_log app`（备用窗口）
3. **Cursor skill / 规则** — 对话结束写入 `对话/` 页
4. **ChatGPT 导出** — 插件入库或 `capture --chatgpt`  

项目列表是**工具设置**（插件「添加工程」，可随时加仓），不是每次要你拍板的产品决策。

口诀：**RAG 负责找；Logseq 负责懂；仓库负责算得对；Cursor 负责改工程。**

## 四层

| 层 | 工具 | 写什么 | 不写什么 |
|----|------|--------|----------|
| 懂 | Logseq OG 打开的图（默认本仓 `out/notes`；用户也可自持仓外图） | 概念、对照、对话提炼 | 整段聊天、契约数字 |
| 找 | RAGFlow（可选） | 用户投喂的脱敏 md | 本仓不去解析兄弟仓 PDF |
| 算得对 | 各工程仓 | 计划、交接、公式账 | 本仓不改那些仓 |
| 原文 | Zotero 等（用户侧） | 用户自己的附件 | 不拷进本仓 |

## 和 Cursor / ChatGPT 项目对接

工程仓继续用各自 IDE 推进。在 **Logseq 插件** 添加工程并点「更新镜像」（或 CLI `project add` / `catalog`）。镜像是只读的。

不要：把工程仓当成 Logseq 图根；不要把 `docs/` 链进笔记图；不要把笔记图加进那些仓库的 Cursor 工作区。契约：`docs/contracts/project-bridge.md`。

## 页名

- `软件/*`、`概念/*`、`公式/os-*`、`案例/<video-id>`、`文献/<citekey>`、`对话/YYYY-MM-DD-主题`
- `对接/Cursor`、`对接/ChatGPT`、`工程/<id>/…`（工程文档镜像）
- 文件名：`/` → `___`（OG 默认）

## 许可

独立引擎可自选许可证；不要改名发行 Logseq，不要闭源分发改过的 OG。非正式法律意见。
